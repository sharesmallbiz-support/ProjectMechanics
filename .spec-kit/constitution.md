# Business Document Spec Kit Constitution

## Purpose

This constitution defines the non-negotiable principles that govern all business documents created using this toolkit. These principles ensure consistency, quality, and professionalism across all documentation projects.

---

## Core Document Principles

### 1. Clarity Above All

**Every document must be clear, concise, and purposeful.**

- Use plain language unless technical terminology is required
- Define all acronyms and jargon on first use
- Structure content logically with clear headings and sections
- One main idea per paragraph
- Active voice preferred over passive voice

### 2. Audience-First Design

**Every document must serve its intended audience.**

- Identify primary and secondary audiences in the spec
- Match tone and detail level to audience needs
- Provide executive summaries for leadership audiences
- Include appropriate technical depth for specialist audiences
- Consider cultural and organizational context

### 3. Data-Driven Content

**All claims, recommendations, and conclusions must be supported by evidence.**

- Cite sources for external information
- Include data, metrics, and quantitative support
- Distinguish between facts, assumptions, and opinions
- Document methodology for analysis and recommendations
- Provide appendices for supporting data

### 4. Professional Quality

**Every document must meet professional standards.**

- Free of spelling and grammatical errors
- Consistent formatting throughout
- Professional visual design
- Appropriate use of graphics and visual aids
- Complete and accurate citations

### 5. Structured Approach

**Every document must follow the four-phase workflow.**

- **SPEC** - Complete specification before planning
- **PLAN** - Detailed outline before task breakdown
- **TASK** - Task list approved before production
- **PRODUCE** - Systematic execution with quality gates

No phase can be skipped. Each phase must be validated before proceeding.

## Document Standards

### Required Sections

Every business document must include:

1. **Title Page** - Document title, author, date, version
2. **Executive Summary** - High-level overview (1-2 pages max)
3. **Table of Contents** - For documents over 5 pages
4. **Main Content** - Organized with clear sections
5. **Conclusion/Recommendations** - Clear takeaways
6. **Appendices** - Supporting data and details
7. **References** - Sources and citations

### Formatting Standards

- **Font:** Professional sans-serif (Arial, Calibri) or serif (Times New Roman, Georgia)
- **Size:** 11-12pt body, 14-18pt headings
- **Margins:** 1" on all sides
- **Line Spacing:** 1.15 or 1.5 for readability
- **Page Numbers:** All pages except title page
- **Headers/Footers:** Document title, section, or organization name

### Visual Standards

- **Tables:** Used for structured data comparison
- **Charts:** Appropriate type for data (bar, line, pie, scatter)
- **Images:** High resolution, properly attributed
- **Diagrams:** Clear labels and legends
- **Color Palette:** Professional, accessible (WCAG 2.1 AA compliant)

## Quality Gates

### Specification Gate

Before proceeding to PLAN phase:

- [ ] Purpose clearly defined
- [ ] Audience identified and characterized
- [ ] Scope boundaries established
- [ ] Success criteria defined
- [ ] Constraints documented
- [ ] Deliverable format specified

### Plan Gate

Before proceeding to TASK phase:

- [ ] Document outline complete
- [ ] All spec requirements addressed in plan
- [ ] Data sources identified
- [ ] Visual elements planned
- [ ] Tone and style defined
- [ ] Review process established

### Task Gate

Before proceeding to PRODUCE phase:

- [ ] All sections have assigned tasks
- [ ] Dependencies identified
- [ ] Resources allocated
- [ ] Timeline established
- [ ] Tasks properly sequenced
- [ ] Acceptance criteria defined

### Production Gate

Before finalizing document:

- [ ] All content sections complete
- [ ] Data verified and accurate
- [ ] Formatting consistent throughout
- [ ] Spelling and grammar checked
- [ ] Peer review completed
- [ ] Spec requirements validated
- [ ] Final quality review passed

## Tone Guidelines

### Professional Documents (Default)

- Formal but accessible
- Objective and fact-based
- Respectful and inclusive
- Clear and direct
- Avoid colloquialisms

### Executive Communications

- Concise and strategic
- High-level focus
- Action-oriented
- Confident but not arrogant
- Bottom-line first

### Technical Documents

- Precise and detailed
- Domain-specific terminology appropriate
- Methodical and thorough
- Include necessary technical depth
- Clear explanations for complex concepts

### Collaborative Documents

- Inclusive and consultative
- Balanced perspectives
- Transparent about trade-offs
- Constructive and solution-focused
- Acknowledge contributions

---

## Ethical Standards

### Honesty and Integrity

- Never fabricate data or sources
- Acknowledge limitations and uncertainties
- Disclose conflicts of interest
- Present balanced perspectives
- Correct errors promptly

### Confidentiality

- Respect proprietary information
- Follow data classification policies
- Obtain permissions for sensitive content
- Redact confidential information in shared versions
- Secure document storage and transmission

### Attribution

- Cite all sources
- Credit contributors
- Respect intellectual property
- Obtain permissions for copyrighted material
- Acknowledge AI-generated content where used

---

## Version Control

All documents must maintain:

- **Version Number** - Semantic versioning (1.0, 1.1, 2.0)
- **Revision History** - Table of changes with dates
- **Author Information** - Primary author and contributors
- **Review Status** - Draft, Under Review, Approved, Final
- **Distribution List** - Who has access to each version

---

## Accessibility

All documents must be accessible:

- Screen reader compatible
- Alternative text for images
- Sufficient color contrast
- Clear heading hierarchy
- Readable fonts and sizes
- Logical reading order
- Accessible table structure

---

## Compliance

Documents must comply with:

- Organizational style guides
- Industry regulations (where applicable)
- Legal requirements
- Privacy laws (GDPR, CCPA, etc.)
- Trademark and copyright law
- Internal policies and procedures

---

## Continuous Improvement

This constitution should evolve based on:

- Feedback from document users
- Lessons learned from projects
- Changes in organizational standards
- Industry best practices
- Technology improvements
